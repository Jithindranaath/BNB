# T-004 · Gateway PancakeSwap write-capability probe

Date: 2026-09-07. **Verdict: Gateway CAN write to PancakeSwap v3 on BSC.**
The "assume quote-only" premise in `plan.md` T-004 / `architecture.md` §13 is
**outdated** — it was true when Hummingbot only listed PancakeSwap as an
arbitrage price source; the Gateway connector has since gained full AMM + CLMM
write support.

## What was checked

Hummingbot Gateway **v2.16.0** (Docker `hummingbot/gateway:version-2.16.0`, tag
`2.16.0` does not exist — it is `version-2.16.0`; `latest` == this).

### 1. Source (release tag v2.16.0)

- `src/connectors/pancakeswap/pancakeswap.config.ts`
  - `tradingTypes = ['amm', 'clmm', 'router']`
  - `networks = [...].filter(n => ['mainnet','arbitrum','base','bsc'].includes(n))` → **`bsc` supported**
- `src/connectors/pancakeswap/clmm-routes/` — the V3 route set:
  `pool-info`, `position-info`, `positions-owned`, `quote-position`, `quote-swap`
  (reads) and **`open-position`, `add-liquidity`, `remove-liquidity`,
  `close-position`, `collect-fees`, `execute-swap` (writes)**.
- The write routes build calldata with `@pancakeswap/v3-sdk`
  `NonfungiblePositionManager.{addCallParameters,removeCallParameters,collectCallParameters}`
  and submit `positionManager.multicall([calldata], txParams)` **with a signer**,
  then parse logs for the position — i.e. exactly the
  `decreaseLiquidity → collect → burn → mint` flow that `spec.md` §6.3 has us
  doing by hand.
- `src/app.ts` registers `/connectors/pancakeswap/{router,amm,clmm}`.

### 2. Running container

```
docker compose --profile trading up -d gateway     # v2.16.0, dev mode, :15888
GET /                                  -> {"status":"ok"}
GET /config?namespace=pancakeswap      -> {"slippagePct":2,"maximumHops":4,"maximumSplits":4}
GET /connectors/pancakeswap/clmm/pool-info?network=bsc&poolAddress=0x3669…2050
    -> 404 {"error":"NotFoundError","message":"Pool not found: 0x3669…2050"}
```

The `clmm/pool-info` route is **registered and reachable**, and `network=bsc`
reaches the BSC code path (`getV3PoolInfo` → `poolContract.token0()/token1()`).
It returns null → "Pool not found" **only because the stock image has no working
BSC RPC** — startup also logged `Ethereum (mainnet): Unable to fetch block number
- https://eth.llamarpc.com`. This is a config gap, not a capability gap.

## Gaps / follow-ups

| Gap | Where it's fixed |
|---|---|
| Stock image ships no working BSC RPC → reads against `network=bsc` return null | T-041/T-043 setup: mount `conf/chains/ethereum/bsc.yml` (or env override) pointing at `BSC_RPC_URL` |
| No on-chain add/remove-liquidity tx executed via Gateway yet (needs BSC RPC + an imported funded wallet) | T-043 — real tiny position, open → adjust → close |
| Gateway v2.16.0 binds `0.0.0.0` in our compose and warns; fund-moving routes need `GATEWAY_API_KEY` | before T-043: bind `127.0.0.1`, set an API key, scope the wallet |

## Decision (updates architecture.md §13)

`pcs-rebalancer` Tier 2 execution:
- **Primary:** Gateway CLMM routes (`open-position` / `remove-liquidity` /
  `collect-fees` / `add-liquidity`).
- **Fallback:** our own viem `NonfungiblePositionManager` path (`spec.md` §6.3) —
  we build the decision logic for T-042 regardless and can wire it to a signer.
- **Final choice made in T-043** after a real dry run (testnet or tiny mainnet
  position). Do not delete the fallback until Gateway is proven end-to-end.

`bnb-grid` Tier 2 (T-041) still uses the Hummingbot API grid controller, not
Gateway — unaffected by this finding.
